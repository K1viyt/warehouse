# Интерфейс «СЕКЦИЯ»

Ветка: feature/frontend-warehouse-ui. База изменений бэкенда сохранена отдельно в 39da1a1.
Сценарии: вход/выход, регистрация, ожидание активации, каталог, создание и просмотр товара, профиль, управление пользователями.
Приход, списание, остатки, редактирование и удаление товаров не добавлены: соответствующих API пока нет.

## Запуск
В WSL, в /home/vlad/projects/warehouse, с уже настроенной WAREHOUSE_DATABASE_PASSWORD:

    bin/rails db:migrate
    bin/rails warehouse:demo_catalog
    bin/rails server -b 127.0.0.1 -p 3000

Открыть http://localhost:3000/. Использовать существующего администратора.
Если первоначального администратора ещё нет, существующий db/seeds.rb принимает WAREHOUSE_ADMIN_EMAIL и WAREHOUSE_ADMIN_PASSWORD через окружение. Пароль не хранится в исходниках.
Задача warehouse:demo_catalog добавляет BOLT-M8, DOWEL-8, SCR-4.5 и не перезаписывает существующие товары. Остатки не создаёт.
Демонстрационные аккаунты для проверки создавались только в test-БД; в development их нет.

## Организация кода
- app/controllers/workspace_controller.rb: HTML-оболочка и выдача актуального CSRF-токена; ответы не кешируются.
- app/views/workspace/: HTML-шаблоны, общая сцена склада и формы доступа.
- app/javascript/controllers/workspace_controller.js: Stimulus, навигация, формы, панели, состояния загрузки, каталог и пользователи.
- app/javascript/lib/api.js: запросы JSON, сессионные cookie, CSRF, обработка HTTP/сетевых ошибок и ответа 204.
- app/javascript/lib/presentation.js: безопасное экранирование данных, подписи ролей/статусов, сообщения ошибок, явное сопоставление иллюстраций по SKU.
- app/assets/stylesheets/section_*.css: отдельно базовые элементы, формы доступа, рабочая область, адаптивность и шрифты; порядок загрузки задан явно.
- app/assets/images/section/: локальные оптимизированные WebP.
- app/assets/fonts/: Manrope и лицензия OFL. Внешние CDN во время работы не требуются.

## Правила интеграции
Все изменения данных идут через существующие POST/PATCH/DELETE API. Поля имеют корневые ключи user/login/product.
Перед изменяющим запросом клиент получает токен для текущей cookie через GET /interface/csrf. Это позволяет войти снова после блокировки/сброса сессии и учитывать смену сессии в другой вкладке.
CSRF-защита не отключается. После входа/выхода HTML загружается заново.
Форма не показывает успех до подтверждения сервера. При ошибке введённые поля остаются; повторная отправка заблокирована на время запроса.
Пароль не меняет регистр и не обрезается. Email нормализует модель. Регистр SKU сохраняется согласно текущему контракту.
Данные пользователя экранируются при построении карточек и таблиц. Сообщения ошибок вставляются через textContent.
Незавершённые запросы списка отменяются при смене раздела/фильтра; поздние ответы не заменяют новый экран.
Фотографии — типовые иллюстрации, не точные технические изображения каждого артикула. Только три известных SKU сопоставлены конкретным фото; остальные получают общий складской фон.
Изображение прямого чёрного самореза заменяет первоначальный вариант. Сцена склада используется для регистрации, входа и ожидания.
Операторам скрыт раздел пользователей; окончательное ограничение доступа выполняет сервер.
Пустые списки, ошибки, загрузка, pending и blocked имеют отдельные состояния.

## Проверки
Автоматически: 48 тестов, 212 assertions, без failures/errors; Ruby-стиль новых файлов; синтаксис JavaScript; git diff --check.
Новые интеграционные проверки выполняют запросы с настоящей CSRF-защитой: вход, сохранение/повторное чтение товара, выход, отказ без токена, обновление токена после смены сессии.
Brakeman 8.0.6: 0 ошибок, 0 предупреждений. bin/brakeman с --ensure-latest останавливается из-за доступной версии 8.1.0; зависимости в этой работе не обновлялись.

В браузере с включённой CSRF-защитой проверены:
- Неверный пароль; вход с верхним регистром email.
- Несовпадающие пароли; успешная регистрация; ожидание и проверка статуса.
- Активация, блокировка, разблокировка; фильтры и вторая страница пользователей.
- Дубликат артикула и сохранение заполненной формы; успешное создание; сохранность после перезагрузки; просмотр карточки.
- Безопасное отображение названия с HTML-разметкой как текста.
- Отсутствие админ-раздела у оператора, переход по прямому #users.
- Блокировка уже вошедшего пользователя и повторный вход администратором после сброса сессии без CSRF-ошибки.
- Адаптивная ширина 390 px: нет горизонтального переполнения страницы. Таблицы прокручиваются в своём контейнере.
- Отсутствие ошибок JavaScript в консоли во время проверенного сценария.

Широкая таблица, нативный dialog с фокусом и Escape, видимый фокус, текстовые подписи ошибок и prefers-reduced-motion предусмотрены.
Для браузерной QA в test-среде можно задать UI_BROWSER_TEST=1: это ВКЛЮЧАЕТ CSRF-защиту, обычно отключённую Rails для интеграционных тестов.
Не запускайте обычный bin/rails test одновременно с тестовым сервером: тесты пересоздают данные test-БД.
