# СЕКЦИЯ — графическое техническое задание

Снимок требований и реализации от 15.10.2026. Основание текущего поведения: код `ced61fb` в ветке `feature/frontend-warehouse-ui`. Складские операции показаны как следующий этап, а не как готовый функционал.

## Открыть документ

- **section-spec.drawio** — главный редактируемый документ. Открыть в draw.io Desktop либо через «Файл → Открыть с устройства» на https://app.diagrams.net/.
- **section-spec.html** — интерактивный просмотр в браузере: страницы, масштаб, переходы и сворачивание ветвей. Для загрузки официального viewer.diagrams.net нужен интернет.
- **section-spec.pdf** — все 18 страниц для чтения и передачи преподавателю, без редактора и без интернета.
- **overview.png** — обзор дерева.
- **qa-results.csv** — отдельный шаблон результатов тестера, UTF-8 с BOM; разделитель — точка с запятой.

На странице 00 нажмите «Открыть требования» внутри нужной ветви. Значок −/+ сворачивает краткое описание, сохраняя название раздела. Вверху каждой страницы — «К дереву», внизу — предыдущая и следующая страницы. В редакторе доступен переход по ссылке выделенной фигуры.

## Содержание

00 — дерево; 01 — назначение и роли; 02 — регистрация; 03 — вход и профиль; 04 — жизненный цикл пользователя; 05 — администрирование; 06 — каталог; 07 — остатки; 08 — приход и списание; 09 — журнал и назначения; 10–11 — текущие API; 12 — модель данных; 13 — интерфейс и безопасность; 14–15 — 32 QA-сценария; 16 — план и открытые решения; 17 — правила приёмки и источники.

В документе 64 пункта требований и контекста. Цвет и подпись показывают: есть в реализации, частично, план, открытый пробел или правило. «Есть» не означает «принято независимым тестером». Проценты готовности не назначены, поскольку согласованного способа их расчёта нет.

## Работа тестера

1. Подготовить собственное окружение по `docs/frontend.md` и записать проверяемый SHA.
2. Начать с QA-01…QA-26. QA-27 проверяет существующий фундамент остатков; QA-28…QA-32 требуют будущей реализации.
3. В `qa-results.csv` указать статус Passed / Failed / Blocked / Not run, версию, факт, ссылку на дефект или доказательство. Все исходные результаты — Not run.
4. При дефекте записать предусловия, шаги, ожидание и фактический результат. Пробелы из ТЗ не выдавать за успешно пройденные проверки.

## Обновление и проверка документа

Редактируйте `section-spec.drawio` в draw.io; после ручной правки повторно экспортируйте PDF и HTML. `requirements.json` и `build_spec.py` сохранены как исходники первоначальной генерации: повторный запуск Python перезапишет drawio и не сохранит ручную геометрию. Изменяйте требования в одном выбранном источнике, затем синхронизируйте остальные форматы.

Проверено автором: XML — 0 ошибок/предупреждений; все 18 страниц экспортированы штатным draw.io 32.4.1 и просмотрены; PDF содержит 18 страниц; внутренние ссылки ссылаются на существующие страницы. В браузере проверены переход к регистрации, возврат к дереву, сворачивание и раскрытие ветви. Эти проверки касаются документа и не заменяют QA приложения.
